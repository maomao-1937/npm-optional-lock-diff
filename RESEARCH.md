# Research and scope

Primary sources reviewed on 2026-11-12 in Asia/Singapore for the 2026-11-11 America/Denver batch.

- On November 7, 2026, an npm user reported that `npm update --package-lock-only` removed five versionless platform-package rows while the optional dependency declarations remained. The reporter observed that a later `npm ci --dry-run` rejected the changed lockfile in their environment. The maintainer closed the report on November 10 as a duplicate of the unpublished-optional-dependency issue. A contributor explained that PR #10240 addressed CI validation of missing placeholders and described row preservation during update as separate work. [npm/cli #10258](https://github.com/npm/cli/issues/10258), [npm/cli #10193](https://github.com/npm/cli/issues/10193), [npm/cli #10240](https://github.com/npm/cli/pull/10240)
- A December 2024 report described OS/CPU variants being pruned when reinstalling with a pre-existing `node_modules`. This is a historical report with a linked Arborist fix. It covers a different trigger from the November 2026 report. [npm/cli #7961](https://github.com/npm/cli/issues/7961), [npm/cli #8184](https://github.com/npm/cli/pull/8184)
- npm documents `packages` as a map of package locations relative to the project root, typically using `""` for the root. It distinguishes regular package metadata from link records. This implementation uses that map and ignores the v2 compatibility dependency tree. [npm lockfile format](https://docs.npmjs.com/cli/v11/configuring-npm/package-lock-json/#packages)
- Node.js documents an ancestor `node_modules` search that skips an ancestor directory already named `node_modules`. This CLI uses the directory order for package-record lookups within the lockfile root. It does not execute Node's package or module loader. [Node.js CommonJS module documentation](https://nodejs.org/api/modules.html#loading-from-node_modules-folders)
- `npm ci` checks and installs a project in its configured environment. A text or generic JSON diff shows row edits. The additional check here relates a removed row to a still-declared optional edge and accounts for a retained visible copy elsewhere in that importer's ancestor chain. It operates on two saved lockfiles independently of the machine's OS and CPU. [npm ci documentation](https://docs.npmjs.com/cli/v11/commands/npm-ci/)

The fixture pairs are synthetic. They verify the comparison rule, including a versionless record, without attempting to reproduce either npm issue. The detector can miss losses when an importer moves or changes the spec string. An unrelated version or placeholder at a reachable path can still provide recorded coverage. These choices follow the tool's location-based comparison and cannot establish npm installability.
